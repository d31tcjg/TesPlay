# TesPlayer integration

TesPlay uses the player and contracts packages from [rdvnit/TesPlayer](https://github.com/rdvnit/TesPlayer), pinned at `dfd05ae757652353aa38ec186569477419c5e15a`. Their source lives in `vendor/tesplayer`; the reference website and its broker/backend are not copied. `npm run build` rebuilds both packages before the website. `npm run check:player` verifies every bundled source file against its pinned provenance manifest; tests rebuild the packages first. Updates use `npm run sync:player -- --source /path/to/TesPlayer --revision <full-commit-sha>`, described in [architecture and maintenance](refactor-audit.md). The bundle has no local source patches: the audio-unlock, silent-video clock and pause/resume timing fixes live in canonical TesPlayer.

`src/tesplayer-adapter.ts` maps existing TesPlay playback URLs into validated engine sessions. Existing authenticated proxies retain account/profile scoping and upstream URL protection. HLS playlists are inspected with size/depth limits to discover qualities, audio renditions, live windows and AES-128 protection. Auto quality initially selects the highest advertised rendition at or below 1080p; it is not a bandwidth-adaptive policy. Plex compatibility requests H.264/AAC reencoding, rather than retaining incompatible tracks. Long VOD playlists retain their bounded segment references across probing and seeking; live streams keep a rolling window. The media proxy keeps child references stable on repeated playlist reads. Provider startup and segment timeouts allow time for upstream transcoding and cold network connections. Direct-source probes retain a shorter deadline. Auto mode can remux existing H.264 video, while forced compatibility reencodes it. Startup reads duration metadata first and computes the precise duration only when metadata is absent; this avoids unnecessary reads at the end of long files/HLS movies. Upstream sockets are reused only for the same origin and validated DNS address. Playback has bounded 16-second audio and 24-frame video queues. These changes reduce avoidable startup work and provide buffering headroom, but provider/network and transcoding capacity still determine throughput. No general-purpose transcoder or DRM bypass is added.

`src/TesPlayer.tsx` owns canvas playback, controls, captions, progress checkpoints and teardown. Plex HLS playback sends an authenticated heartbeat every 15 seconds to the registered transcode session, including while paused; ending/closing playback stops upstream pings. The proxy applies the same viewer, profile and library checks as media reads. On resume, the engine holds the saved position until audio arrives, holds at the end of buffered audio during underruns, and recalculates pending video deadlines when audio reanchors. Decoder preroll is excluded from display. This prevents delayed audio from dropping valid resumed frames or letting recovery seek beyond received media. It serializes destruction before replacing a playback engine. Selecting a title or opening phone pairing resumes the shared audio context in the screen's own gesture, before lazy imports or resolution requests. The stream starts automatically where the browser permits. Phone selection cannot grant a gesture on the target screen: if audio remains locked, the player waits without starting decoders or advancing watch progress and shows Enable playback on this screen. Silent video uses the monotonic presentation clock. Resume, household profile history and next-episode actions stay wired into the host. Captions use plain text, with optional pasted VTT/SRT limited to 2 MB. The player and playlist editor do not invoke device file pickers, avoiding managed Chromium file-picker restrictions. Seek, volume, speed, rotation, fit/fill, fullscreen and advertised quality selection use the same engine.

YouTube uses the disabled-by-default yt-dlp resolver (`server/youtube.js`). Native installs explicitly enable it; Compose uses an optional `youtube` sidecar with no published port. The resolver validates video IDs, restricts stream hosts to YouTube/googlevideo, caps concurrent jobs and sanitizes errors. Only same-origin opaque media references reach the client. Previously saved YouTube embed URLs are interpreted as video IDs and routed to the resolver; no iframe API is loaded. Expired URLs can be refreshed by closing/reopening the title.

Use HTTPS (or localhost) and a current browser with WebCodecs video/audio decoding support. Missing decoder support gives a visible error without a second player. TesPlay's production CSP permits WebAssembly compilation for the bundled MPEG audio decoder, restricts scripts to self and disables frames. The in-app preview browser may lack WebCodecs even when Chrome on the same machine supports them.

The Node server, SQLite, mounted media and optional resolver run on your host or containers. TesPlay requires this backend and cannot be deployed as a static-only website. See [deployment](deployment.md), [verification](verification.md) and [tested vehicles](compatibility.md).

## Controls and remote selection

Sutro SVG controls are adapted to the existing canvas engine, with an always-expanded volume slider, a center play/pause touch button, and animated left/right double-tap seeking by ten seconds. Controls hide after inactivity during playback. The single fullscreen button targets the video surface rather than the entire dialog; browsers lacking element fullscreen get an immersive viewport fallback.

Phone remote commands include `load` with a validated media item. Rooms are scoped to both account and profile. Only the session that created the room receives playback commands. Phones browse the normal permitted libraries and send playable titles to the screen; folders and series continue to browse on the phone. Provider playback endpoints enforce access again when the screen resolves the selected title.

The Cinema phone remote separates playback, Browse, and Queue. Its artwork, play/pause state, seek window, volume, mute, subtitles, and fullscreen indicator come from the paired screen's engine snapshot. The screen publishes an allowlisted snapshot once per second; the phone polls every 1.25 seconds. Telemetry is scoped to the same account/profile, and only the host session can publish. Playback URLs are excluded from the returned item. Offline screens and browsers needing a local sound-unlock gesture disable playback controls.

Commands also include absolute seeking (`seek-to`), mute, caption toggle, speed, and queue refresh. Queues accept permitted playable titles across providers; folders and series remain browse destinations. Queue changes refresh the screen's library, and movies/audio can advance to the next queued title.

## Playback selection and continuity controls

The host details panel discovers tracks without instantiating a player. Explicit settings enter `Player` and the adapter before engine load, while direct play retains profile/automatic defaults. Plex advertises stable audio/subtitle IDs, enforces selected audio on its transcode session, and provides current resume time. HLS audio selections preserve quality and vice versa, and advertised WebVTT renditions are included. Finite container audio uses Mediabunny's per-type track selectors, bound to the representation ID issued by the authenticated media proxy (or a strong ETag for external direct sources). The proxy hashes local file size/mtime/inode, or the registered upstream source URL/total size/ETag/Last-Modified, within the opaque resource binding. Temporary redirect URLs are transport details and do not change that file identity. Sources without a readable finite representation do not advertise file track selectors.

`TesPlayer` exposes audio beside subtitles and previous/next beside play/pause. The host handles series/queue order and the selector below the player. Timeline checkpoints include play/pause/stop state, and a completed engine generation sends only one completion checkpoint. Plex synchronization failures retain local progress. Recent Plex history and Watchlist reads are separate from the local library and scoped to the linked profile and shared library grants.

Implementation references: [Plex Media Server API](https://developer.plex.tv/pms/), [YouTube video metadata](https://developers.google.com/youtube/v3/docs/videos), and [YouTube's three-minute Shorts criteria](https://support.google.com/youtube/answer/15424877).
